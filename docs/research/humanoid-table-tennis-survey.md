# Humanoid Table Tennis: Open-Source Landscape Survey

*Compiled from berkeley-us.md, china-games.md, code-sweep.md, cross-checked against verification.md (authoritative on disagreements). Checked 2026-08-27.*

## 1. Landscape

Humanoid table tennis is young; almost nothing production-ready is open source. The headline real-world result is UC Berkeley's [HITTER](https://arxiv.org/abs/2508.21043) — 92.3% return rate, a 106-shot rally on a Unitree G1 — but it ships **no code**; its WBC foundation ([BeyondMimic](https://arxiv.org/abs/2508.08241)'s `whole_body_tracking`/`motion_tracking_controller`) is public and MIT-licensed but has zero table-tennis content. Purdue's [PACE](https://github.com/purdue-tracelab/PACE-ICRA2026) is the only fully open, MIT, trainable, table-tennis-specific humanoid RL codebase (Booster T1), with no weights or deploy code. [hitchopen/HOPE](https://github.com/hitchopen/HOPE) is a separately-run "open challenge" platform (Apache-2.0, built on BeyondMimic) that ships a checkpoint and a full train→deploy pipeline, but only for the Agibot A3 — its G1 support is docs-only. China's 2nd World Humanoid Robot Games (Aug 2026) ran table tennis as an official, HOPE-based event on standardized A3 hardware across 12 teams (gold PKU-BAAI, silver HKU "SMASH," bronze SJTU-SII, per [Global Times](https://www.globaltimes.cn/page/202608/1369009.shtml)), but no team's match code was released — including [SMASH](https://arxiv.org/abs/2604.01158), the only humanoid system here using onboard-camera-only ball sensing like ours. DeepMind's non-humanoid arm lineage is the most mature thread but is now archived and dataset-only. Nobody has published a complete open pipeline combining RGB-D-only sensing, a Booster/Unitree-class humanoid, and a trained targeted-strike policy — we'd assemble one from PACE's env/predictor, HOPE's pipeline pattern, and BeyondMimic's WBC/deploy code.

## 3. Ball prediction and whole-body control, per approach

- **HITTER** ([arXiv:2508.21043](https://arxiv.org/abs/2508.21043), no code): classical model-based planner recomputes ball trajectory every step from 360 Hz OptiTrack mocap (poly-fit velocity), yielding racket target position/velocity/timing (<7.5 cm error at 0.5 s pre-strike). WBC is a separate 50 Hz PPO policy trained in Isaac Lab on BeyondMimic-style human-swing references, reward = imitation + goal-tracking + regularization, deployed zero-shot (92.3% real return rate, 106-shot rally).
- **PACE** ([repo](https://github.com/purdue-tracelab/PACE-ICRA2026)): no separate classical planner — a lightweight learned MLP predicts the ball's post-bounce hitting apex inline, trained against a physics ground-truth predictor, feeding both a footwork cue and a dense reward. WBC is one end-to-end PPO policy mapping ball state + proprioception + predicted apex directly to joint commands across 4,096 parallel envs.
- **HOPE** ([repo](https://github.com/hitchopen/HOPE)): an explicit "no-spin" trajectory planner (Python + low-latency C++/ROS2) computes the racket target from mocap ball tracking. WBC is a unified forehand/backhand PPO policy trained via the BeyondMimic recipe (SMPL-X-retargeted human swings as reward priors), exported to ONNX and run through a native C++ deploy runner on real A3 hardware.
- **SMASH** ([arXiv:2604.01158](https://arxiv.org/abs/2604.01158), no code): fully egocentric — a ZED X stereo camera detects the ball at 60 Hz and ego-localizes at 120 Hz onboard, no external mocap at deploy time. WBC is a motion-matching RL policy trained against a Motion-VAE-expanded strike library plus task commands at a 120 Hz control loop; real-world return rate 65% (20 trials, ego-camera-only) and 59.7% over a 642-launch endurance test.

## 4. Fit for our target — top 3 to build on

1. **[PACE-ICRA2026](https://github.com/purdue-tracelab/PACE-ICRA2026)** — closest hardware match (Booster T1, same vendor as K1) and simulator match (Isaac Sim/Isaac Lab, matches our evaluator). *Take:* the `t1_tt` task structure and reward design, the aerodynamics/air-drag module, the prediction-augmented-PPO runner (learned ball-apex predictor + its reward-shaping trick), serve-range randomization. *Write ourselves:* K1 URDF/joint remap (23→22 DoF) and a G1 variant (29 DoF); swap the predictor's ball input from PACE's own (undocumented, possibly-mocap) source to our RGB-D + paddle-IMU stack; all deployment/inference code (none shipped); HIM Arena's legal-return/target-hit/landing-error/latency metric wrappers; pin Isaac Sim 4.5.0/Isaac Lab 2.1.0 or validate our NVIDIA box's install against the "degrades on 5.0+" warning.
2. **[hitchopen/HOPE](https://github.com/hitchopen/HOPE)** — only repo with a working checkpoint and a full train→export→MuJoCo-check→C++-deploy pipeline; its mocap-fed BeyondMimic recipe is the closest analog to using our own G1-retargeted mocap as reward priors. *Take:* overall pipeline layout, the ONNX-export + MuJoCo sim-to-sim gating harness, the ball planner as a starting scaffold, the BeyondMimic motion-imitation reward recipe. *Write ourselves:* A3(31-DoF)→K1/G1 URDF and paddle/end-effector remap; replace OptiTrack/Chingmu mocap adapters with our RGB-D pipeline; our own checkpoint (theirs is A3-specific); G1 support here is docs-only, so we'd be first to actually run it.
3. **[HybridRobotics/whole_body_tracking](https://github.com/HybridRobotics/whole_body_tracking) + [motion_tracking_controller](https://github.com/HybridRobotics/motion_tracking_controller)** (BeyondMimic) — the literal WBC stack HITTER is built on, MIT, already has a G1 task config, and uniquely has a working C++/ROS2 real-hardware deploy path. *Take:* the PPO motion-imitation scaffold and reward structure (`r = w_i·r_i + w_g·r_g + w_r·r_r`), the G1 config, the ONNX/C++/ROS2 deploy pipeline as our real-robot bridge. *Write ourselves:* the entire table-tennis layer — ball spawn/physics, racket-contact and target/landing reward, a ball-prediction module (none exists here; borrow PACE's predictor or [EmbodiedVision's EKF](https://github.com/EmbodiedVision/tabletennis-spin-impacts)), goal-command generation from the planner, K1 port, RGB-D + paddle-IMU integration into the observation space.

## 5. Licensing constraints

All three top picks are permissive: PACE, `whole_body_tracking`, `motion_tracking_controller` are MIT; HOPE is Apache-2.0. No CC-BY-NC or research-only license turned up in this sweep. Caveats: [LATENT](https://github.com/GalaxyGeneralRobotics/LATENT), [tt3d](https://github.com/cogsys-tuebingen/tt3d), [tabletennis-spin-impacts](https://github.com/EmbodiedVision/tabletennis-spin-impacts), and [SMPLOlympics](https://github.com/SMPLOlympics/SMPLOlympics) all report NOASSERTION/no LICENSE file — default all-rights-reserved applies; treat as read-only reference without contacting authors. More relevant: our own vendor's RL scaffolding — [booster_gym](https://github.com/BoosterRobotics/booster_gym), `booster_train`, `booster_deploy`, `booster_robotics_sdk` — is all **NOASSERTION** too (per verification.md's direct check); only `robocup_demo`/`booster_champion_example` are Apache-2.0, `booster_assets` is BSD-3-Clause, and `sim-3v3-simple-framework` is the org's one MIT repo. DeepMind's dataset repo is Apache-2.0 for code but CC-BY for "other materials" (attribution required).
